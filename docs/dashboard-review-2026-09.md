## P0 — تعرّض ملفات: `/files/*` مفتوح للإنترنت بالكامل

`shadapp-backend/routes/web.php:9-19` — خارج أي middleware مصادقة:

```php
Route::get('/files/{path}', function (string $path) {
    $clean = ltrim($path, '/');
    if (! Storage::disk('public')->exists($clean)) abort(404);
    $response = Storage::disk('public')->response($clean);
    $response->headers->set('Access-Control-Allow-Origin', '*');   // ← أي موقع
    return $response;
})->where('path', '.*');
```

اللي بيتخزّن هناك: عقود PDF، **إثباتات الدفع**، صور التوقيعات، ومستندات العملاء المرفوعة (`FileController.php:92`, `PaymentController.php:159,246`).

**التقدير الصحيح للخطر:** الأسماء عشوائية — Laravel's `store()` بيولّد hash من ٤٠ خانة — فالتعداد (enumeration) غير عملي. الخطر الحقيقي إن **أي رابط يتسرّب مرة = وصول عام دائم**: في سجلّات السيرفر، في `Referer` header، في history المتصفح، في رسالة واتساب، في تذكرة دعم. مفيش انتهاء صلاحية ومفيش تحقق. و`Access-Control-Allow-Origin: *` معناها إن أي موقع خبيث يقدر يقراهم بـ JS لو عرف المسار.

الداشبورد **واعي بده**: `src/proxy.ts:29-36` فيه كومنت `KNOWN RESIDUAL RISK` بيشرحه بدقة ويقول "قبل الاعتماد على سرية الملفات". التوثيق ممتاز — بس البند لسه مفتوح، والموبايل كمان بيعتمد على نفس المسار (`api_client.dart:resolveFileUrl`).

**الحل** (باك اند، مش داشبورد): نقل الملفات لقرص `local` ووراها endpoint مصادَق بيتحقق من ملكية المورد، أو روابط موقّعة قصيرة العمر (`URL::temporarySignedRoute`). أي الاتنين بيتطلب تعديل `resolveFileUrl` في الموبايل والداشبورد — وهو سبب إضافي لتوحيدها أولًا (بند ٤ تحت).

## P1 — مفيش أي حدود أخطاء (Error Boundaries)

فحصت `src/app/`: **مفيش** `error.tsx` ولا `not-found.tsx` ولا `loading.tsx` ولا `global-error.tsx`.

في Next App Router، أي استثناء أثناء الرندر في أي صفحة من الـ ٢٢ بيوصل لشاشة الخطأ الافتراضية بدل واجهة التطبيق. والملاحظة دي مترابطة مع اللي فوق: `types/index.ts:36` بيعرّف `value: string | null` و`amount: string | number` — فأي `.toFixed()` على قيمة نصية بيرمي أثناء الرندر.

الحل تلات ملفات صغيرة. ده أعلى مكسب لأقل مجهود في القائمة كلها.

## P1 — `api.ts:32` بيرمي على أخطاء بلا `config`

```js
async (err) => {
  const config = err.config;
  config.__retryCount = config.__retryCount || 0;   // ← TypeError لو config undefined
```

`err.config` بيبقى `undefined` لما الخطأ يترمي من داخل request interceptor — وده وارد هنا، لأن `getActiveSocketId()` (سطر ٢١) بينده كود Echo. ساعتها الـ interceptor نفسه بيرمي `TypeError`، ويستبدل الخطأ الأصلي، **والفرع بتاع 401 تحته مابيوصلوش أصلًا**.

الحل سطر: `const config = err.config; if (!config) return Promise.reject(err);`

**ملاحظة تانية في نفس الملف** (سطر ٤٢): `const isClient = !!localStorage.getItem('client')` — لو الـ localStorage اتمسح والكوكي لسه client، المستخدم بيتوجّه لـ `/login` بدل `/client-login`. الكوكي `sa_session_type` هو المصدر الصح، بس مش مقروء من الكلاينت (httpOnly). حل بسيط: كوكي غير-httpOnly للنوع بس، أو الاعتماد على الـ redirect من السيرفر.

## P2 — `resolveFileUrl`: ١٨ نسخة، و٤ سلوكيات مختلفة

`resolveFileUrl` معرّفة **١٨ مرة**، و`FILE_BASE` متكررة ~١٥ مرة. والأهم إنها **اتفرّعت فعلًا**:

| النسخة | التوقيع | السلوك |
|---|---|---|
| ١٦ ملف | `(url: string)` | بتكسر لو وصلها مصفوفة |
| `PaymentsTab.tsx:15` | `(url: string \| string[])` | بتاخد `url[0]` |
| `ClientPayments.tsx:262-264` | inline جوه حلقة الرندر | بتفكّ المصفوفة يدويًا |
| `finance/page.tsx:391` | inline | بتفكّ المصفوفة يدويًا |

السبب إن `types/index.ts:67` بيعرّف `proof_file_url?: string | string[]` — فكل واحد لمس إثباتات الدفع اكتشف لوحده إنها ممكن تكون مصفوفة وحلّها بطريقته.

**مش باج حالي** — فحصت كل مواضع استخدام `proof_file_url` وكلها بتتعامل مع المصفوفة. بس ده يعني إن السلامة الحالية جاية من إن ٣ ناس تفادوا نفس اللغم بالصدفة، مش من تصميم. أول واحد يستخدم واحدة من الـ ١٦ نسخة التانية مع إثبات دفع هيلاقي رابط مكسور.

## اللي شغّال كويس فعلًا

- **`proxy.ts`** — حماية مسارات حقيقية من جهة السيرفر (`/dashboard` تتطلب `staff`، `/client-dashboard` تتطلب `client`/`sub_user`) قبل ما أي كود صفحة يشتغل. والكومنت بيشرح ليه ده أفضل من `useEffect` redirect.
- **نمط الـ httpOnly cookie + proxy** — التوكن مابيوصلش لـ JS أصلًا. ده أنضف من أي حاجة في الموبايل (اللي بيستخدم secure storage بس التوكن بيعدي في كود التطبيق).
- **`session.ts`** — ملف صغير موثّق كويس، وبيربط `maxAge` بـ `config/sanctum.php` مع شرح لنتيجة عدم التزامن.
- **`utils.ts`** — نضيف ومتغطى بتستات (١٣ دلوقتي بعد `asSettingFlag`).
- **التستات** — ١١٢ تست بتغطي `lib/` بالكامل + المكونات الحرجة أمنيًا (`ActivityFeed` بعد إصلاح الـ XSS) + مسارات الدخول.

### مؤجّل عن قصد

- **تقسيم `dashboard/page.tsx`** — بعد ما يبقى فيه تستات تحميه، مش قبل.
- **TanStack Query / Server Components / useMemo** — دي اقتراحات بلا قياس. لو فيه بطء محسوس، نقيسه الأول ونشوف مصدره. الإضافة دلوقتي بتزوّد تعقيد بدون دليل على المشكلة.
- **الوصولية (`role="dialog"`, focus trap)** — حقيقية ومؤكدة (صفر نتائج للاتنين في المشروع)، بس مالهاش أثر على سلامة البيانات. شغل مستقل يتعمل دفعة واحدة.
